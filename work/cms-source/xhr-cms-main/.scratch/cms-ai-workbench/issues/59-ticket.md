# 59 — 恢复中断的整站应用

**审查编号** C1

**优先级** P1

**状态** 已通过隔离环境实际栏目写入与恢复验收

## 问题与依据

应用意图按原请求恢复。后台审核可在应用中断期间推进页面包修订，导致旧请求无法续跑，新确认又被旧意图挡住。见 `cms-core/src/main/java/com/xinhongru/cms/template/SiteModelWorkbenchApplyService.java:169`、同文件第 452 行及 `cms-core/src/main/java/com/xinhongru/cms/template/PackageDraftAnalysisService.java:690`。

## 修改范围

- 在整站应用入口回读现有结构、实际栏目及导航回执，显示已确认完成的步骤、待核对步骤和变化的修订。
- 原修订仍有效时沿用原请求续跑。确有修订冲突时，提供授权审核人显式结束旧意图并按最新数据重新预览和确认的入口。结束操作保留核对证据，复用已建且一致的栏目，对归属不一致的栏目要求人工处理。
- 复用应用服务的权限、锁和修订校验。检查关闭与继续执行竞争及已完成请求的重复提交。

## 回归验收

- [x] 经工作台应用接口在栏目实际写入后、后续步骤提交前人为中断。同修订重试成功，栏目仅保留一份。
- [x] 第二位审核人推进同包修订。旧请求保留冲突及已写步骤，获授权的审核人结束旧意图并重新确认后继续完成，已建栏目 ID 与导航归属可核对。
- [x] 并发恢复与结束、无权关闭、关闭后重放旧请求均通过。已回读来源、栏目、导航和包修订。
- [x] 在浏览器实点恢复入口、结束和重新确认按钮，补验不同站点的关闭范围。

留证使用隔离站点，保存两次确认、修订、步骤回执和栏目 ID。依赖真实结构应用、导航和页面包回执；可独立于切站、签收和部署工单实施。

## 2026-11-27 验证记录

实现整站应用弹窗回读现有 CMS 栏目和导航阶段，整包修订变化后由审核人在原范围显式结束旧确认。旧请求在新确认生效后仍可取得原关闭回执。已落到导航应用阶段的申请复用原导航回执，重新确认整包修订后继续。

Windows Temurin 21 隔离快照的 `SiteModelWorkbenchApplyRecoveryTest` 通过 1 项，覆盖同修订不可关闭、另一审核推进包修订、过期关闭被拒、关闭留档、旧请求重放返回相同结果及新预览可用。该测试使用替身服务，实际栏目 ID、并发恢复及多管理员浏览器操作仍按验收项复核。

## 2026-11-27 隔离实际写入复核

Windows Temurin 21 启动工作台后端 15360 和一次性调试后端 15362，共用本轮新建的合成 MySQL 与 Redis。在导航第一笔事务提交后、第二笔回执事务执行前暂停并结束 15362。数据库独立连接已读到栏目，工作区可读到 `APPLYING` 导航回执。隔离计划以合成确认稿开始，审核、预览、应用和回读使用正常接口。

- 站点 #59 在整包修订 7、导航修订 2 暂停。预览返回 `CONFIRMED_RETRY` 与 `NAVIGATION_CHECKPOINT`。在 15360 重放原确认后返回 `APPLIED`。原页 `index.html` 与 `about.html` 分别保留 #6003、#6004，数据库只有原根栏目及这两条记录。
- 站点 #61 在相同阶段暂停。模型已关闭，测试将一条合成页面预置为可人工审核的跳过状态。第二位审核人 #130 经包审核接口将修订推进至 9。预览返回 `CLOSE_STALE_INTENT` 与 `NAVIGATION_CHECKPOINT`，普通角色的结束请求返回 HTTP 403。并发的继续和结束分别返回 `PARTIAL` 和 `CLOSED`。同范围重新预览确认后返回 `APPLIED`，原页仍对应 #6101、#6102，导航修订 2、整包修订 9，两个节点均无漂移。随后重放旧确认仍返回原关闭回执。
- 在合成站 #65 再次中断并确认第一笔数据库写入。第二位审核人将包修订 7 更新至 8。Chrome 通过「核对或继续上次栏目应用」打开实际恢复弹窗，显示包修订及导航检查点。实点「确认结束旧申请」获得 `CLOSED`，再点「确认并应用」获得 `APPLIED`。界面和数据库均保留 Home #6501、About #6502，原页分别为 `index.html`、`about.html`。将此申请在合成站 #59 的范围提交关闭，返回 HTTP 409。
