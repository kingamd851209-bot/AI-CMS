# 64 — 超过 1,000 条核验记录的整站续核

**审查来源** C4，承接[工单 61](61-ticket.md)。
**优先级** P2。
**状态** 暂缓。2026-11-27 用户说明目前项目很少会达到这一规模，优先验收账号权限与内容撤下。遇到实际站点接近 1,000 条核验记录时再评估。当前版超出支持规模时显示待签收。

## 交付范围

管理员应能在同一站点、页面包、结构修订和部署版本下分批核对到最后一条。单次请求的扫描量应有上限。第 61 号工单已经修复正好 200 条时的误报，并提供最多五批的续核。现有实现每次按扩大后的预算重新扫描，不能直接调大常量充当增量处理。

复用已有工作区、核验指纹与失效规则，保存完成位置和累计证据。页面与资源所属部署发生变化时提示重新核对，并保留旧历史回执。栏目及详情页、媒体、交互要求、例外和链接检查都应计入最终汇总。定位从 [WorkbenchReleaseReviewService.java](../../../cms-site/src/main/java/com/xinhongru/cms/template/WorkbenchReleaseReviewService.java) 与 [WorkbenchStaticLinkCheckService.java](../../../cms-site/src/main/java/com/xinhongru/cms/template/WorkbenchStaticLinkCheckService.java) 开始。

## 验收

- [ ] 构造超过 1,000 条核验记录的隔离站。最后一条确实完成后才允许签收，各批次汇总与一次独立清点结果一致。
- [ ] 记录各次请求实际扫描的文件数量。同版本刷新、重试和重复提交续核凭证均正确恢复，无重复计数、漏页或从头扫描全部既有文件。
- [ ] 在处理中途修改页面、资源或修订，核对旧凭证失效；另一站点或部署方式的凭证不能推进本次签收。
- [ ] 通过工作台正常入口保存、离开、返回、续核并读取最终回执，分别登记 CMS 托管与独立静态结果。
