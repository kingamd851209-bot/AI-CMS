## 实施边界

复用导出器识别正式页面、片段和渲染回执的规则，将当前 CMS 正式页面集合与包内清单对照，列出缺失和多余路径。保留已有哈希、资源和页面摘要核对，兼容可验证的旧清单。当前集合不可获取时返回明确错误，避免把证据缺失当作签收通过。旧归档保留历史版本用途，当前签收以对应版本重新导出和部署为准。

- [x] 同一隔离站分别新增、移除和改名正式页，首页保持原样，旧包核验非零退出并报告集合差异。

在一次性 MySQL 和 Redis 的合成站 #56，通过 CMS 发布接口生成 `index.html`、`home-entry.html` 和 `about.html`。独立导出包含三个正式页面及 CSS、JS、SVG 各一份，使用回环端口 18766。基线执行 `verify-static.py --record` 核验 6 文件、0 项异常，退出码 0。暂时移走 CMS 产物 `about.html` 后，独立端仍保留同一清单和页面，核验退出码为 1，报告 `obsolete-page`；工作台整站签收 API 将独立部署列为待处理并显示该路径。恢复 CMS 产物后，同一命令再次核验 6 文件、0 项异常，退出码 0，签收接口中独立部署项回到 `READY`。本轮完成的是独立部署核验，其他栏目绑定仍单列在整站报告中。
