# CMS 系统审查记录 · 2026-11-27

当前最急的是管理员账号授权。一个已经登录且具备有效站点角色的后台账号，可能改到权限高于自己的目标账号。另一项应立即排期的问题是内容删除，数据库记录与访客静态页面可能朝相反方向变化。

## 审查范围与证据

以桌面工程的本机源码、需求基线、现行隔离发布清单及三站既有工单为准。按调用链抽查了后台和会员认证、站点权限、内容和表单写入、MyBatis 映射及建库 SQL、动态与静态发布、工作台任务与签收、Vue 双模式构建、独立导出和 Nginx 示例。P0 表示先处理权限接管风险，P1 表示应优先处理的授权、数据或发布完整性缺陷，P2 表示有明确触发条件的功能或部署问题。

下表为源码确认，只有明确标为“实测”的项目另有本轮运行证据。源码目录未检出 Git 元数据，部署清单中的 JAR 哈希与磁盘文件一致，尚未逐类证明部署字节码与桌面源码相同。安全项依据控制器、服务、拦截器和持久化实现判定。未操作真实账号权限、口令、发布状态或业务数据。

## 本轮验证及待办

- 使用本轮桌面源码、隔离发行目录的现有依赖，在临时目录分别运行 `npm run build`、`npm run build:workbench`，均通过。客户包没有工作台页面同名分包，工作台包有对应分包。桌面源码旁的依赖副本缺少可运行的 vue-tsc 入口，直接运行类型检查无法代表源码能否构建。五阶段进度现有 Node 测试 6/6 通过。
- 从发布清单取得 JAR 和前端入口并核对 SHA-256。两者与当前磁盘文件一致。另核对 Vite 配置、工作台主视图、签收组件、进度工具四份源码，与发行前端源快照逐字节一致。当前 Ubuntu 用户环境未找到工程要求的 SDKMAN JDK 21，本轮未重新运行 Maven 后端套件。
- 绕过代理读取本机。三个 CMS 首页（17651、17652、17653）均返回 200。工作台路径 15190 普通 HTTP 请求返回 302。碧朗湾与晨光独立站清单分别列 35、19 张正式页面，与当前 CMS 静态源目录对照，页面集合及逐页摘要一致。这项检查没有覆盖全部资源与交互。
- 金隅独立预演 18429 的首页首次返回 200，随后在原验收回执相同的环回地址连续三次返回空响应，导出清单也读取失败；当时监听进程仍在，同站 CMS 首页返回 200。故障定位到独立预演访问链路，根因尚未确定。应单独查预演进程错误输出、静态目录及同一请求的处理结果，再恢复该站独立签收。
- 安排修复时先做 A1–A3 的授权矩阵，再做 B1–B4 的删除、撤下、草稿和交付完整性。随后检查会员凭据迁移、工作台恢复与并发。每批分别记录数据库状态、CMS 访客结果、静态文件和独立访客结果。
